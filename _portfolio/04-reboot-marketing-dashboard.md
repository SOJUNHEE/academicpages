알디콤을 모티브로 한 가상의 숙취해소 젤리·음료 브랜드 Reboot의 미국 채널 담당 마케터 1명이 트렌드 확인부터 콘텐츠 제작, 광고 심의, 고객 응대, 성과 확인까지 한곳에서 처리하는 업무용 웹 대시보드다. 6명 팀 프로젝트에서 팀장을 맡았고, FDA·FTC 기준에 걸리는 표현을 걸러 내는 광고 심의(컴플라이언스) 탭과 고객 문의에 안전한 답장을 보내는 고객 응대(CS) 탭의 규칙과 기능을 담당했다. 대시보드와 연결되는 미국 소비자용 브랜드 홈페이지(제품 소개·자사몰·크리에이터 전용 링크·관리자 매출·챗봇)는 다른 팀원이 만들었고, 홈페이지 챗봇은 내가 만든 광고 심의 규칙으로 답변을 검사한다.

## 한눈에 보기

| 수치 | 의미 |
|---|---|
| **4분 30초 → 1분** | 광고 문구 검토 시간 (본인 1회 측정 · 검토 요청·2차 검토 제외) |
| **87 / 87** | 2020년 FDA 숙취 제품 경고장 원문 문구 (규칙을 만들 때 쓴 사례) |
| **17 / 23** | 규칙을 만들 때 쓰지 않은 새 위반 문장 판정 (보강 전 11) |
| **91개** | 5일간 팀 인스타그램 게시물 (팀 결과 · 릴스 4,961회) |

## 배경 · 문제

- 미국 FDA는 2020년 7월, 숙취를 치료·완화·예방한다고 주장한 제품을 판매한 7개사에 경고장을 보내 해당 제품을 승인받지 않은 신약으로 보았다(FDA 공지 2020-07-29). 국내에서 쓰던 '숙취해소' 중심 문구를 미국 광고·SNS·고객 답장에 그대로 쓰면 이런 규제 위험이 생길 수 있었다.
- 미국 채널 담당자 1명이 여러 채널의 문구와 고객 문의를 함께 처리해야 해, 문구마다 위반 여부를 사람이 일일이 찾아보는 방식으로는 속도와 판단 일관성을 유지하기 어려웠다.

## 목표

- 팀 목표는 미국 채널 담당 마케터 1명이 쓰는 업무 대시보드를 7개 탭으로 나눠 만드는 것이었다.
- 개인적으로는 광고·SNS·고객 답장 문구를 내보내기 전에 FDA·FTC 기준으로 걸러 내고, 걸린 이유와 근거를 함께 보여 주며, 담당자가 확인한 뒤에만 고객에게 발송되는 흐름을 만드는 것을 목표로 했다.

## 데이터

- 심의 근거로 FDA 공개 경고장에서 옮긴 실제 문구 사례 87개와 공개 규정(21 CFR 등)을 사용했다.
- 출처: FDA, "FDA Sends Warning Letters to Seven Companies Illegally Selling Hangover Products" (2020-07-29) https://www.fda.gov/food/hfp-constituent-updates/fda-sends-warning-letters-seven-companies-illegally-selling-hangover-products
- 제품 정보는 팀이 정한 가상 브랜드 사양서 기준이고, 고객 문의·주문·판매 데이터는 실제 기업 데이터가 아닌 가상(더미) 데이터다.
- 현재는 시뮬레이션 데이터 기반으로 구현했으며, 실제 운영 환경에서는 ERP/WMS/TMS API 또는 데이터베이스와 연동할 수 있도록 확장할 수 있다.

## 해결 방법

- 문구를 채널·제품별로 판정하는 서버 심의 규칙 17개(R1~R17)를 설계해, 표현마다 통과·조건부·검토·수정·사용 불가 단계와 법적 위험 신호(빨강·노랑·초록)를 함께 보여 주게 했다.
- 걸린 표현마다 FDA 경고장의 실제 문구 사례와 근거 조문, 바꿔 쓸 표현을 함께 보여 줘, 담당자가 '왜 안 되는지'와 '어떻게 고칠지'를 한 화면에서 판단할 수 있게 했다.
- 제품 사양과 다른 표현(맛·형태·탄산 여부)을 잡는 규칙과, 측정 전인 열량을 강조하는 표현을 잡는 규칙을 팀 최종 검토 의견에 맞춰 추가했다.
- 규칙이 놓칠 수 있는 위험은 Claude API로 2차 심의를 받게 하고, 그 판단 기준(페르소나)을 정리했다. 심의 결과는 법적 승인이 아니라 1차 참고용임을 화면에 표시했다.
- 고객 응대에서는 답장 초안이 문구 심의와 담당자 승인 조건을 통과해야 Gmail로 한 번만 발송되도록 하고, 브랜드 가이드에 맞춘 답장 예시를 기준으로 삼았다.
- 만든 규칙과 화면은 ChatGPT로 교차 검토를 받아 빠진 표현과 오류를 보강했다.
- 제출 후에는 팀 저장소를 개인 저장소로 분리해 Vercel에 배포하고, 채용 담당자가 로그인 없이 볼 수 있도록 보기 전용 시연 모드(저장·발송·AI 실행 잠금, 방문자 문의 등 개인정보 숨김)를 넣었다. 공개 범위는 직접 정했고, 구현과 점검에는 AI 코딩 도구(Claude Code)를 활용했다.

## 주요 기능

- 광고 문구를 넣으면 걸린 표현, 사용 가능 여부, 근거 경고장 문구, 바꿔 쓸 표현을 함께 보여 줘, 담당자가 수정 방향을 바로 정할 수 있다.
- 문구를 최대 30개까지 한 번에 심의하고 점검 기록과 점검자를 남겨, 캠페인 문구 묶음을 한꺼번에 확인하고 나중에 근거를 다시 볼 수 있다.
- 고객 문의는 답장 초안 → 문구 심의 → 담당자 승인 → Gmail 발송 순서를 거치게 해, 사람 확인 없이 자동으로 나가는 답장을 막았다.
- 보기 전용 시연 모드에서는 화면을 모두 둘러볼 수 있지만 저장·발송·AI 실행은 잠기고, 방문자 문의·상담 질문·API 키 정보는 보이지 않는다.
- 브랜드 홈페이지(팀원 담당)는 미국 소비자에게 제품을 소개하고 자사몰 구매·크리에이터 전용 링크 매출을 관리하며, 관리자 화면에서 상품·프로모션과 매출을 운영한다. 대시보드는 이 판매 데이터를 받아 성과 분석에 쓴다.
- 홈페이지 챗봇(Ask Reboot)은 사람 검수 없이 소비자에게 바로 답하는 곳이라, 답변을 보내기 전에 서버에서 대시보드와 같은 광고 심의 규칙(13개)으로 검사하고 걸리면 다시 쓰게 하거나 고정된 안전 답변을 보낸다.

## 구조

- Flask 단일 서버에 탭별 폴더(서버 routes.py, 화면 static/)를 두는 구조다. 팀원은 각자 탭 폴더와 이니셜 브랜치에서 작업한 뒤 Pull Request로 병합했다.
- 화면은 빌드 도구 없는 HTML·CSS·JavaScript이고, 서버는 Flask-Login 로그인·CSRF 보호, SQLAlchemy(로컬 SQLite, 배포 Neon Postgres)를 쓴다.
- 광고 심의·고객 응대의 AI는 Anthropic Claude API, 다른 탭은 OpenAI API를 쓴다. API 키는 서버 환경변수나 설정 화면에만 두고 코드에 넣지 않는다.
- 심의 규칙은 서버용 JSON과 화면용 JavaScript 엔진에 같은 기준으로 두며, 브랜드 홈페이지의 상담 응답도 같은 규칙 파일로 검사한다.
- 개인 공개본은 Vercel(서버리스)과 Neon Postgres에서 운영하고, 브랜드 홈페이지와는 토큰 인증 CSV API로 판매 데이터를 주고받는다.

## 내 기여와 팀의 역할

**내가 맡은 일**

- 팀장: 일정·이슈 우선순위·담당 조정
- 광고 심의 규칙 17개(R1~R17)와 법적 위험 신호 설계
- FDA 경고장 문구 사례 87개와 근거 조문 정리
- AI 2차 심의 판단 기준(페르소나) 작성
- 고객 응대 답장 승인 조건·Gmail 발송 흐름·답장 예시
- 인스타그램 제품 홍보 숏폼 영상 제작 (Higgsfield 활용)
- 제출 후 개인 저장소 분리, Vercel 배포, 보기 전용 시연 모드 (AI 코딩 도구 활용)
- 브랜드 홈페이지 공개본: 팀 저장소에서 분리, Vercel 배포, 관리자 화면 보기 전용 모드(쓰기 요청 차단·방문자 정보 숨김, 테스트 23개 추가) (AI 코딩 도구 활용)

**다른 팀원이 맡은 일**

- 광고 심의·고객 응대 화면 흐름 재설계와 공통 UI 정리 (PM)
- '실제 미국 광고와 비교' 기능, 규제 소식 자동 수집처 추가 (PM)
- 홈·인사이트·콘텐츠·파트너·성과분석 탭
- 브랜드 홈페이지 제작: 제품 소개·자사몰 구매·크리에이터 전용 링크·관리자 매출·문의함·챗봇·게임 (팀원 3명)

## 시행착오

- 규칙을 만든 뒤 처음 보는 위반 문장 23개로 시험하니 11개만 맞았습니다. 놓친 문장을 보고 단어 변형과 표현을 보강해 17개까지 올렸고, 규칙만으로 못 잡는 나머지는 AI 2차 심의와 담당자 승인 단계로 넘겼습니다.
- 공개 시연에서 화면 자동 저장이 막히자 '저장하지 못했습니다' 알림이 반복되는 문제를 실제 사이트에서 찾아, 시연 모드에서는 저장하지 않고 정상 응답만 돌려주도록 고쳤습니다.

## AI 활용 방식

- 광고 심의의 2차 판단과 고객 답장 초안에 Claude API를 씁니다. 결과는 1차 참고용이며 최종 판단과 발송은 담당자가 합니다.

**AI에 맡긴 일**

- 코드 초안과 문서 작성 (Claude, ChatGPT)
- 인스타그램 제품 홍보 숏폼 영상 제작 (Higgsfield)
- 규칙·화면 교차 검토 (ChatGPT)
- 개인 공개본 배포와 시연 모드 구현·점검 (Claude Code)

**직접 판단한 일**

- 어떤 표현을 막을지와 판정 단계·위험 신호 기준 결정
- 경고장 사례·근거 조문 선택과 팀 검토 의견 반영
- 공개 범위 결정: 보기 전용, 개인정보 숨김

**검증**

- 심의 결과를 법적 승인처럼 보이지 않게 '1차 참고용'으로 표시하고, 사람 승인 없이는 고객에게 발송되지 않게 했습니다.

## 결과

- 서버 심의 규칙 17개와 FDA 경고장 문구 사례 87개를 갖춘 광고 심의 탭, 승인 후에만 발송되는 고객 응대 탭을 팀 대시보드 안에서 동작하도록 완성했다.
- 개인 공개본 기준(2026-11-05)으로 광고 심의·고객 응대 자동 테스트(Python 54개, JavaScript 19개)를 포함한 대시보드 전체 테스트 420개가 통과한다.
- 배포된 사이트에서 로그인 없이 7개 탭 열람, 저장·발송·AI 실행 차단, 방문자 개인정보 숨김, 브랜드 홈페이지 판매 데이터 연동을 직접 확인했다.
- 규칙 점검(tabs/compliance/tests/engine.test.js, 2026-11-05 실행): 규칙을 만들 때 쓴 FDA 경고장 원문 문구 87개는 모두 걸렸다(규칙 미탐지 0개). 규칙을 만들 때 쓰지 않은 새 위반 문장 23개로는 17개를 맞게 판정한다(규칙 보강 전 11개). 87/87은 규칙이 모든 광고 위험 표현을 잡는다는 뜻이 아니며, 나머지는 AI 2차 심의와 담당자 승인으로 보완한다.
- 본인이 사용자로서 같은 업무를 1회씩 직접 재 본 결과: 광고 문구 검토는 4분 30초 → 1분이었다(기존 방식은 생성형 AI 검색과 규제 사이트 확인이며, 검토 요청·2차 검토·실제 미국 광고 비교는 뺀 시간). 같은 방식으로 카드뉴스 7분 28초 → 2분 38초, 이미지 11분 16초 → 5분 19초, 경쟁사 10개 가격 조사 13분 → 리포트 3분이었다(콘텐츠·인사이트 탭은 다른 팀원 담당).
- 팀 결과: 5일 동안 인스타그램 게시물 91개를 만들었고(프로젝트 기록 기준 약 80%를 대시보드로 기획·제작), 릴스 누적 조회수 4,961회를 기록했다(발표 시점).
- 시간 비교는 본인 1회 측정이고 가상 브랜드로 진행해, 실제 기업 업무에서 같은 효과가 난다고 일반화할 수는 없다. 실제 마케터나 고객에게 사용해 보게 한 검증은 아직 하지 않았다.

## 한계와 개선 과제

- 한국어 부정문('저칼로리 식품은 아니에요')과 질문형 문장('Is it carbonated?')까지 위반으로 잡는 오탐을 확인했고, 규칙 보정이 남아 있다.
- 심의 결과는 법률 자문이 아니므로, 실제 광고 집행 전에는 법무 검토가 필요하다.
- 실제 Gmail 계정과 실제 고객 문의로는 검증하지 않았다.
- 서버리스 배포라 업로드 파일과 생성 이미지가 임시로만 저장된다. 실제 서비스라면 외부 저장소와 권한별 접근 관리가 필요하다.
- 시간 비교는 1회 측정이다. 여러 사람이 여러 번 측정해야 효과를 말할 수 있다.
